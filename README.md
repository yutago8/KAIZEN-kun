# KAIZEN-kun

上野裕太さんの日次・週次KAIZENサイクル支援エージェント「KAIZEN君」の **Claude Code（claude.ai）Routine版** セットアップ・運用リポジトリ。

Cowork版（毎時スケジュールタスク）からの移行先。コードは持たず、**起動プロンプトのマスターとセットアップ手順**を管理する。

## 構成

```
claude.ai Routine（毎時実行・毎回新規セッション）
  ├─ モデル: Claude Sonnet 5
  ├─ コネクタ: Notion / Slack / Google カレンダー
  ├─ Notion MCP …… 運用仕様書・各DBの読み書き（毎回仕様書を読んで動く）
  ├─ Slack MCP …… チャンネル/スレッド読み取り・スレッド返信・DM
  ├─ Bash + curl …… Incoming Webhook 投稿（KAIZEN君ボット名義 → メンション通知が鳴る）
  └─ サブエージェント（Task/Explore）…… 読み取り系の情報収集を委譲
```

- **設計の核心**: ロジックはコードやプロンプトに埋め込まず、[運用仕様書ページ](https://app.notion.com/p/3b8d761688188102b068d4c1fea58e62) に置く。エージェントは毎回このページを読んで動く。仕様変更＝ページ編集のみ。
- **記憶**: AIエージェント実施ログDB。起動時に直近24時間分を読み、アクション後に必ず書く。
- **通知**: Cowork版の唯一の弱点（Slack MCPは本人名義投稿→通知が鳴らない）を、Incoming Webhook（ボット名義投稿）で解決。これが移行の最大の動機。

## セットアップ手順

### 1. 環境のネットワーク設定（Webhook用・必須）

Claude Code の実行環境（環境「デフォルト」）は初期状態で `hooks.slack.com` への外部接続がブロックされている。

1. https://claude.ai/code の設定 → Environments（環境）→「デフォルト」→ ネットワークアクセス
2. 許可ドメインに `hooks.slack.com` を追加（または制限を緩和）

> 許可しない場合、Webhook投稿が失敗しSlack MCP投稿にフォールバックする（動作はするが**通知が鳴らない**＝Cowork版と同じ弱点に戻る）。

### 2. Routine（スケジュールタスク）の作成

> ⚠️ API/セッション経由で作成したRoutineにはMCPコネクタとモデル指定を付与できない（組織制限）。**必ず claude.ai の Routines UI から作成**すること。

1. claude.ai の Routines（スケジュールタスク）画面で新規作成
2. 設定:
   - **スケジュール**: 毎時（1時間ごと）。サイレント帯（JST 0:00–7:59）の抑制は仕様書側のロジックが行うため、スケジュール自体は24時間毎時でよい
   - **セッション**: 毎回新規セッションを作成
   - **モデル**: Claude Sonnet 5
   - **コネクタ**: Notion・Slack・Google カレンダー を有効化
   - **プロンプト**: [`kaizen_prompt.md`](./kaizen_prompt.md) の本文（`---` 以下）を貼り付け、`<WEBHOOK_URL>` を実際のWebhook URLに置き換える（実URLはNotionの引き継ぎ書に記載。**このリポジトリにはコミットしない**）

### 3. 初回動作確認

- [ ] Routineを手動実行（または初回の自動実行を待つ）
- [ ] セッションが運用仕様書ページを読んでいる
- [ ] （時刻該当時）#0-神喝 に **KAIZEN君ボット名義** で投稿され、メンション通知が**鳴る**
- [ ] AIエージェント実施ログDBに `[状態] 日次=… 週次=…` 付きで記録される
- [ ] 何もすることがない時刻は投稿もログもなく静かに終了する

### 4. Cowork版の停止（二重起動防止・最重要）

新Routineの動作確認後、**Cowork側のスケジュールタスクを必ず無効化**する。両方動くとリマインドが二重に飛ぶ。

※ 9時台の「朝ブリーフ」はCowork側の別タスクで移行対象外。残す場合はそのままでよい（9:00のWPリマインドが3行以内ルールなのはこの連投配慮のため）。

## 運用

| やりたいこと | 方法 |
|---|---|
| リマインドの時刻・文面ロジックを変えたい | 運用仕様書ページを編集するだけ（次の起動から反映） |
| 一時停止 / 再開 | Routines UI でオフ / オン |
| 起動プロンプト自体を変えたい | Routines UI で編集（このリポジトリの `kaizen_prompt.md` も同期して更新） |
| 動作ログを見たい | claude.ai/code のセッション一覧（Routineが起動したセッション）を開く |

## トラブルシュート

| 症状 | 原因と対処 |
|---|---|
| Slack投稿が本人名義になる / 通知が鳴らない | Webhookが失敗しMCPフォールバックになっている。環境のネットワーク設定で `hooks.slack.com` が許可されているか確認 |
| Notionのページが読めない（404） | Notionコネクタの接続範囲に仕様書・各DB・テンプレート・目標OS/行動原則OSが含まれているか確認 |
| リマインドが二重に届く | Cowork版のスケジュールタスクが動いたまま。無効化する |
| 引用が同じ人物ばかり | 実施ログの直近3件に使用人物が記録されているか確認（仕様書の引用ルール参照） |
